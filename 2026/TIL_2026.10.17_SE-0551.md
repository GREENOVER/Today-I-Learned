## Intro

- **Proposal**: SE-0551
- **Author**: Guillaume Lessard
- **Review Manager**: Doug Gregor
- **Status**: Accepted
- **Implementation**: swiftlang/swift#88152

## Summary of Changes

임의의 값에 대한 단일 원소 `Span`을 만드는 이니셜라이저와, 임의의 mutable 값에 대한 단일 원소 `MutableSpan`을 만드는 이니셜라이저를 추가해요.

## Motivation

가끔 단일 값과 `Span`을 받는 API 사이를 이어주는 어댑터가 필요할 때가 있어요. 지금도 `CollectionOfOne`의 `span` 프로퍼티를 써서 단일 값을 `Span` 파라미터에 넘길 수는 있지만, 이 방법은 `Span`에는 필요 없는 복사를 요구하고, noncopyable 값은 아예 지원할 수 없어요. 그래서 단일 값을 제자리에서 borrow하는 이니셜라이저를 `Span`, `RawSpan`, `MutableSpan`, `MutableRawSpan`에 제공하자는 거예요.

이 이니셜라이저들은 `withUnsafePointer(to:)`, `withUnsafeMutablePointer(to:)`, `withUnsafeBytes(of:)`, `withUnsafeMutableBytes(of:)`의 안전한 버전 역할도 합니다.

## Proposed Solution

`Span`과 `MutableSpan`에는 단일 값에 대해 count가 1인 span을 만드는 새 이니셜라이저가 추가돼요.

```swift
let header = PacketHeader(...)
let c = checksum(Span(ofOne: header).bytes) // borrows `header` in place

var timestamp = UInt64.zero
var span = MutableSpan(ofOne: &timestamp)
parser.read(into: span.mutableBytes)        // writes into `timestamp`
```

마찬가지로 `RawSpan`과 `MutableRawSpan`에는 단일 값의 바이트에 대한 span을 만드는 이니셜라이저가 추가돼요.

```swift
let header = PacketHeader(...)
let c = checksum(RawSpan(bytesOf: header))

var timestamp = UInt64.zero
var bytes = MutableRawSpan(bytesOf: &timestamp)
parser.read(into: bytes)
```

## Detailed Design

### Span

```swift
extension Span where Element: ~Copyable {
  /// Create a span over the single value passed as a parameter.
  ///
  /// - Parameters:
  ///   - value: a value to be borrowed by the span
  @_lifetime(borrow value)
  public init(ofOne value: borrowing Element)
}
```

### MutableSpan

```swift
extension MutableSpan where Element: ~Copyable {
  /// Create a mutable span over the single value passed as a parameter.
  ///
  /// The `MutableSpan` created by this initializer will represent a
  /// mutation of `value`.
  ///
  /// - Parameters:
  ///   - value: a value to be mutated through the span
  @_lifetime(&value)
  public init(ofOne value: inout Element)
}
```

### RawSpan

```swift
extension RawSpan {
  /// Create a span over the bytes of the single value
  /// passed as a parameter.
  ///
  /// The `RawSpan` created by this initializer will have a `byteCount`
  /// of `MemoryLayout<Element>.size` bytes.
  ///
  /// - Parameters:
  ///   - value: a value to be borrowed by the span
  @_lifetime(borrow value)
  public init<Element: ConvertibleToBytes>(
    bytesOf value: borrowing Element
  )
}
```

### MutableRawSpan

```swift
extension MutableRawSpan {
  /// Create a mutable span over the bytes of the single value
  /// passed as a parameter.
  ///
  /// The `MutableRawSpan` created by this initializer will represent a
  /// mutation of `value`. It will have a `byteCount` of
  /// `MemoryLayout<Element>.size` bytes.
  ///
  /// - Parameters:
  ///   - value: a value to be mutated through the span
  @_lifetime(&value)
  public init<Element: ConvertibleToBytes & ConvertibleFromBytes>(
    bytesOf value: inout Element
  )
}
```

> `RawSpan`과 `MutableRawSpan` 이니셜라이저는 [SE-0525](https://github.com/swiftlang/swift-evolution/blob/main/proposals/0525-rawspan-safe-loading-api.md)에서 도입된 `ConvertibleToBytes`, `ConvertibleFromBytes` 제약을 사용해요.

### Source Compatibility

이 제안은 추가만 하는 변경이고, 제안된 이니셜라이저들이 기존 심볼을 오버로드하지 않아서 소스 호환적입니다.

### ABI Compatibility

이 제안의 이니셜라이저들은 추가 ABI를 만들지 않는 방식으로 구현될 예정이에요.

이 추가 사항들은 `Span`의 존재를 전제로 하기 때문에, Swift 표준 라이브러리가 OS와 함께 배포되는 Darwin 플랫폼에서는 최소 배포 타깃이 있습니다.

### Implications on Adoption

이 추가 사항들은 도입된 버전의 표준 라이브러리를 필요로 하지만, 부모 타입이 허용하는 만큼 back-deploy가 가능해요.

## Alternatives Considered

### CollectionOfOne의 span 프로퍼티를 계속 쓰기

`CollectionOfOne.span`과 `CollectionOfOne.mutableSpan`도 이미 단일 원소 span을 제공하지만, copyable 타입의 값으로 제한돼요. 또 다른 바인딩의 저장소가 아니라, 그 컬렉션 자신의 저장소에 대한 접근만 제공한다는 한계도 있어요.

### 레이블 없는 이니셜라이저

이 이니셜라이저들은 원래 `Span(header)`, `MutableSpan(&timestamp)`처럼 인자 레이블 없이 제안됐어요. 레이블 없는 표기엔 두 가지 반대 의견이 있었어요. 첫째, Swift에서 레이블 없는 이니셜라이저는 관례적으로 인자의 변환을 뜻한다는 점. 둘째, 사용자가 `Span(someArray)`가 `someArray.span`과 같은 결과를 낼 거라고 기대할 수 있다는 점이에요.

`ofOne:` 레이블은 만들어진 `Span`이 값 1개에 대한 것임을 분명히 하고, 복사 가능한 값에 대해 비슷한 역할을 해온 `CollectionOfOne`을 떠올리게 해줍니다.

### RawSpan과 Span 이니셜라이저에 같은 레이블 쓰기

`Span` 이니셜라이저에 쓴 `ofOne:` 레이블을 `RawSpan`에도 쓸 수 있었어요. 하지만 `ofOne`은 단일 원소를 연상시키는데, `RawSpan`에서 원소는 바이트 하나를 뜻해요. `bytesOf:` 레이블이 복수의 느낌을 적절하게 전달합니다.

### unsafe 바이트 뷰를 위한 RawSpan 이니셜라이저 추가하기

제안된 `RawSpan` 이니셜라이저는 `some ConvertibleToBytes`로 제약돼요. 제약 없이 쓸 수 있는 unsafe 이니셜라이저를 `paddedBytesOf:` 같은 레이블로 추가할 수도 있었어요. 하지만 이니셜라이저가 늘어나는 건 피하고, 현재 API를 조합해서 unsafe한 경우를 해결하는 쪽을 선호해요. 예를 들어 `SIMD3<UInt16>` 인스턴스에서 `RawSpan`을 얻으려면 이렇게 하면 돼요.

```swift
Span(ofOne: coordinates).unsafeBytes
```

## Conclusion

그동안 단일 값을 `Span`을 받는 API에 넘기려면 `CollectionOfOne`을 거치며 복사가 필요했고, noncopyable 값은 아예 불가능했어요. 이 제안의 `ofOne:`, `bytesOf:` 이니셜라이저 덕분에 값을 제자리에서 borrow하거나 mutate하는 span을 바로 만들 수 있고, `withUnsafePointer(to:)` 같은 unsafe API의 안전한 대안도 생겼다는 점이 인상적이에요. 레이블 하나까지 고민해서 정한 과정이 Alternatives Considered에 잘 담겨 있는 것도 흥미로웠습니다 🙌
