## TimelineView란?

공식 문서는 TimelineView를 "여러분이 제공한 스케줄에 따라 업데이트되는 뷰"라고 소개해요. TimelineView 자체는 아무런 모양이 없는 컨테이너고, 그 안에 담긴 콘텐츠를 **정해진 시점마다 다시 그려주는** 역할만 해요.

공식 문서의 첫 예제는 아날로그 타이머의 문자판을 1초마다 갱신하는 코드예요.

```swift
TimelineView(.periodic(from: startDate, by: 1)) { context in
    AnalogTimerView(date: context.date)
}
```

콘텐츠를 만드는 클로저는 `TimelineView.Context` 타입의 입력을 받아요. 이 context에는 업데이트를 일으킨 `date`가 들어 있어서, 위 예제에서는 이 date를 AnalogTimerView에 넘겨 시곗바늘을 어디에 그릴지 알려주고 있어요.

## Context — date와 cadence

`TimelineView.Context`는 타임라인 뷰의 content 콜백에 전달되는 정보예요.

- `date`: 현재 뷰 업데이트를 일으킨 스케줄 상의 날짜
- `cadence`: 타임라인이 뷰를 업데이트하는 속도
- `invalidateTimelineContent()`: 시스템이 타임라인에서 미리 렌더링해둔 뷰들을 초기화

### cadence로 불필요한 디테일 숨기기

cadence는 뷰가 지금 받고 있는 업데이트 속도를 알려줘서, 그보다 빨리 변하는 정보를 화면에서 숨기는 데 쓸 수 있어요. 공식 문서 예제에서는 cadence가 `.seconds` 이하일 때만 타이머의 초침을 보여줘요.

```swift
TimelineView(.periodic(from: startDate, by: 1.0)) { context in
    AnalogTimerView(
        date: context.date,
        showSeconds: context.cadence <= .seconds)
}
```

시스템은 스케줄의 업데이트 속도보다 느린 cadence를 쓸 수도 있어요. 예를 들어 watchOS에서 사용자가 손목을 내려도 뷰는 계속 보일 수 있는데, 이때는 업데이트가 덜 자주 일어나고 그만큼 필요한 디테일도 줄어드는 거죠.

### Cadence의 세 가지 케이스

| 케이스    | 설명                                                         |
| --------- | ------------------------------------------------------------ |
| `live`    | 뷰를 연속적으로 업데이트 (애니메이션을 구동하기에 적합한 고빈도) |
| `seconds` | 대략 초당 한 번 업데이트                                     |
| `minutes` | 대략 분당 한 번 업데이트                                     |

`Cadence`는 `Comparable`을 채택하고 있어서 비교 연산자로 속도를 비교할 수 있어요. 공식 문서는 디지털 타이머의 밀리초 단위를, cadence가 `.live`보다 느릴 때 숨기는 예시를 들어요.

```swift
let hideMilliseconds = cadence > .live
```

## TimelineSchedule — 언제 업데이트할지 정하기

`TimelineSchedule`은 스케줄로 쓸 날짜의 시퀀스를 제공하는 프로토콜이에요. 이 프로토콜을 채택한 타입은 `entries(from:mode:)` 메서드를 정의해서 날짜 시퀀스를 반환하는 방식으로 스케줄을 구현해요. TimelineView를 만들 때 이 스케줄 타입을 넘기고, 타임라인 뷰는 스케줄이 만들어내는 날짜 순서에 맞춰 콘텐츠를 업데이트합니다.

```swift
func entries(from: Date, mode: Self.Mode) -> Self.Entries
```

직접 스케줄 타입을 만들 수도 있지만, SwiftUI는 흔히 쓰이는 빌트인 스케줄 네 가지를 제공해요.

| 스케줄                               | 설명                                                         |
| ------------------------------------ | ------------------------------------------------------------ |
| `everyMinute`                        | 매 분의 시작 시점에 업데이트. 시스템 시계에 맞춰 정렬돼서, 오후 1시에 시작하면 1시 1분, 1시 2분, 1시 3분 식으로 업데이트돼요. |
| `periodic(from:by:)`                 | 시작 시각과 업데이트 간격을 지정해서 규칙적으로 업데이트     |
| `explicit(_:)`                       | 유한하거나 불규칙한 개수의 업데이트가 필요할 때, 날짜 시퀀스를 직접 지정 |
| `animation(minimumInterval:paused:)` | 애니메이션 콘텐츠를 위한 고빈도 업데이트. 일시정지가 가능한 스케줄 |

```swift
static var everyMinute: EveryMinuteTimelineSchedule

static func periodic(from: Date, by: TimeInterval) -> PeriodicTimelineSchedule

static func explicit<S>(S) -> ExplicitTimelineSchedule<S>

static func animation(minimumInterval: Double? = nil, paused: Bool = false) -> AnimationTimelineSchedule
```

### animation 스케줄의 파라미터

- `minimumInterval`: 스케줄이 업데이트되는 최소 간격이에요. `nil`을 넘기면 시스템이 적절한 업데이트 간격을 고릅니다.
- `paused`: 스케줄이 업데이트 생성을 멈출지 여부예요. watchOS 문서에서도, 이 값이 `false`일 때만 뷰가 업데이트된다고 설명해요.

### explicit 스케줄 활용 예

watchOS 문서는 오디오북 앱이 각 챕터가 시작되는 시점에 맞춰 업데이트를 예약하는 걸 예로 들어요. 이럴 땐 `Date` 인스턴스의 배열 같은 시퀀스를 넘기면, 시스템이 시퀀스에 담긴 각 날짜마다 TimelineView를 업데이트해줘요.

### 스케줄이 과거/미래 날짜만 갖고 있다면?

- 과거 날짜만 담긴 스케줄이면, 타임라인 뷰는 스케줄의 마지막 날짜를 보여줘요.
- 미래 날짜만 담긴 스케줄이면, 첫 번째 스케줄 날짜가 올 때까지 현재 날짜로 콘텐츠를 그려요.

## 시스템이 업데이트를 조절한다

watchOS 문서에 따르면, 시스템은 스케줄대로 업데이트를 일으키려고 하지만 시스템의 현재 상태에 따라 업데이트를 지연하거나 미룰 수 있어요. 또 스케줄이 현재 cadence보다 더 자주 업데이트하도록 되어 있으면, 시스템이 cadence 수준으로 업데이트를 조절(throttle)해요. 그래서 콘텐츠를 만들 때는 시스템 시계를 직접 읽기보다, context에 들어 있는 `date`를 써야 합니다.

## watchOS에서 쓰는 TimelineView

TimelineView로 주기적인 UI 업데이트를 예약하면, 앱이 background나 inactive 상태일 때도 업데이트가 계속 실행돼요. 그래서 Always On 상태의 watchOS 앱을 최신으로 유지하기에 이상적이에요. 물론 앱이 foreground에서 실행 중일 때 애니메이션 같은 다른 변화를 구동하는 데도 쓸 수 있어요.

공식 문서의 예제는 사용자 몸속 카페인 양을 매 분마다 다시 계산해서 보여줘요.

```swift
var body: some View {
    VStack {

        // Use a timeline to recalculate the value every minute.
        TimelineView(EveryMinuteTimelineSchedule()) { context in
            // Display the current amount of caffeine in the user's body.
            Text(coffeeData.mgCaffeineString(atDate: context.date) + " mg")
                .font(.body)
                .fontWeight(.bold)
                .foregroundColor(colorForCaffeineDose())
        }

        // Lay out static views here.
        Text("Current Caffeine Dose")
            .font(.footnote)

        Divider()
        ...
}
```

### Always On 상태에서의 동작

- 앱이 활성화되어 foreground에 있을 때 타임라인 스케줄은 `normal` 모드로 실행되고, TimelineView는 `live` cadence의 업데이트를 받을 수 있어요.
- 앱이 Always On 상태로 전환되면 스케줄도 `lowFrequency` 모드로 전환되고, cadence는 일반적으로 떨어지며, 시스템이 미래 업데이트를 한꺼번에 미리 로드할 수도 있어요.
- 성능을 높이기 위해 시스템은 최대 5분 뒤의 미래 뷰를 요청할 수 있어요. 그래서 임의의 미래 시각 `Date`가 주어져도 뷰의 내용을 결정할 수 있어야 해요. 예를 들어 달걀 타이머는 임의의 미래 시각에 대해서도 남은 시간을 계산할 수 있으니 Always On에서 TimelineView를 쓰기에 적합해요.

### 상태별 업데이트 빈도

- background 런타임이 있는 앱(운동, 백그라운드 오디오 앱이나 백그라운드 새로고침 작업을 실행 중인 앱)은 `seconds` 빈도의 업데이트를 받아요.
- inactive 상태이지만 frontmost인 앱은 일반적으로 `minutes` 빈도의 업데이트를 받아요. 다만 짧은 구간 동안 `seconds` 빈도의 업데이트를 요청하면, 가능한 경우 시스템이 그 cadence를 제공해요.

예를 들어 달걀 타이머는 `ExplicitTimelineSchedule`로 카운트다운 대부분은 분 단위 업데이트를, 마지막 1분은 초 단위 업데이트를 설정할 수 있어요.

### cadence에 맞춰 UI를 바꾸는 예시 (타이머 앱)

watchOS 문서의 타이머 앱 예시를 정리하면 이렇게 돼요.

| cadence   | 타이머 앱이 보여주는 것                                      |
| --------- | ------------------------------------------------------------ |
| `live`    | 남은 시간을 분, 초, 1/100초 단위로 표시하고 애니메이션도 재생 |
| `seconds` | 1/100초를 숨기고 애니메이션은 정적 이미지로 대체. 분, 초만 표시 |
| `minutes` | 초도 숨기고 가장 가까운 분 단위로만 표시                     |

## TimelineViewDefaultContext

모든 타임라인 뷰가 쓸 수 있는 구체적인 Context 인스턴스를 가리키는 타입 별칭이에요. 이니셜라이저 중에도 이 타입을 쓰는 형태가 기본으로 안내돼요.

```swift
typealias TimelineViewDefaultContext = TimelineView<EveryMinuteTimelineSchedule, Never>.Context

init(Schedule, content: (TimelineViewDefaultContext) -> Content)
```

## Conclusion

TimelineView는 뷰 자체가 상태를 들고 타이머를 돌리는 대신, "언제 다시 그릴지"를 `TimelineSchedule`로 선언하고 그 시점의 `date`와 `cadence`만 받아 화면을 그리는 구조예요. 시스템이 업데이트 빈도를 조절하는 만큼, 항상 context의 date와 cadence를 기준으로 UI를 구성하는 것이 핵심 포인트 같습니다 🙌
